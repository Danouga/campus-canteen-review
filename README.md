# 食间 · 校园食堂共建网站 MVP

这是一个可运行的**界面与流程原型**。覆盖两个校区，食堂和店铺默认留空；用户可从加号提交共建申请，管理员预览页可审核后暂示 24 小时或直接固定，也可直接维护食堂与店铺资料。首页与食堂展示分开，食堂展示页始终保留添加食堂卡片。支持食堂照片、店铺门面与菜品照片、图片弹窗、美食贴本地演示和简单内容筛选。

## 运行

需要 Node.js 20 或更高版本，以及本机 MySQL 8.0。首次运行先安装依赖：

```powershell
npm install
npm run dev
```

当前本机配置位于被 Git 忽略的 `.env.local`，服务地址默认为 `http://127.0.0.1:4174`。`npm run check` 检查 JavaScript 语法，`node tests/contribution-smoke.mjs` 检查选择性共建和食堂照片的数据流程。数据库连接失败时服务不会启动，避免误写入浏览器备用数据。

## 当前数据模式

- 已接通本机 MySQL 8.0。服务端自动创建 `canteen_guide_mvp` 数据库与 `app_state` 表，以一行 JSON 保存当前 MVP 的完整预览状态。`src/api-repository.js` 通过本机 HTTP API 调用服务端；浏览器不会读取数据库密码。服务端只监听 `127.0.0.1`，且静态文件路由不会提供 `.env.local`。
- MySQL 配置只保存在被 `.gitignore` 忽略的 `.env.local`。未配置 `DB_MODE=mysql` 时自动使用浏览器 `localStorage`；两种模式的数据不会自动迁移。
- 当前单行 JSON 存储适合本机原型验证，正式多用户版本需要拆分数据表、独立图片存储、事务与审核权限。管理员入口没有身份保护，昵称仅供演示，屏蔽词只有少量示例词。**不可直接公开部署。**
- 为避免凭空造学校资料，两校区暂用“校区一/校区二”占位名。管理员可在管理预览页修改。食堂与店铺均从空白开始。

## 可试用的流程

1. 从首页进入“食堂展示”，切换校区；即使已有食堂，也可点击“添加食堂”卡片申请补充。
2. 进入“管理预览”，将申请暂示 24 小时、直接固定或驳回；也可直接添加/编辑/下架与恢复食堂、店铺，管理菜品和图片。
3. 进入已固定的食堂，申请添加店铺；进入店铺查看菜品、图片、营业时间和评论的空状态。
4. 点击食堂、店铺或菜品信息，可以只勾选一项资料提交修改，也可一次选多项；审核卡片显示完整校区、食堂、店铺和菜品位置及每项新值。新增菜品可填写“名称或口味”并附照片。
5. 食堂标题旁可查看照片，图片窗口最后一张空白卡片用于申请上传。店铺标题图、菜品缩略图也打开同一类图片窗口。店铺图片可选择“菜品照片”或“店铺门面”；食堂、店铺卡片顶部会展示已有图片。管理员可直接管理食堂照片，单张限制 900KB。
6. 点击“美食贴”发帖，关联店铺，在富文本编辑器中调整加粗、斜体、标题、列表并插入图片。帖子列表可进入详情页，店铺详情也列出相关帖子。
7. 管理预览页可清空本地测试数据，回到两个校区的空白状态。

## MVP 范围说明

公开用户登录、推荐票、排行榜、美食贴互动（评论、收藏、赞同、反对）及共建态度投票仍未接入。右上角“网站评价规则”说明当前规则与后续计划。正式开放互动前，需要学校登录接口或其他可识别用户的方案，以及服务端审核和权限控制。三维食堂、AI 推荐、微信小程序和赞助仅显示“规划中”页面。
