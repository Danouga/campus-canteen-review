# 食间 · 校园食堂共建网站 MVP

更新日期：2026-10-13｜对应当前工作区实现

**食间是一个由师生共同完善食堂和店铺信息、分享菜品体验，并通过评论与推荐票发现校园美食的网站。**覆盖两个校区，采用空白目录共建，不设置星级打分。

当前已实现目录和详情、图片多图及描述、富文本帖子、评论和态度、共建审核与暂示、推荐票和来源明细、积分占位、用户侧栏、审核员及管理员分工，并接入 MySQL。已接入邮箱与密码登录；收藏、举报申诉、完整审计和公开部署尚未完成。

## 1. 运行

推荐使用已验证的 Node.js 24 环境。首次获取项目后，在交互式终端安装锁定依赖：

```powershell
npm ci
```

### 浏览器预览

没有 `.env.local` 或未设置 `DB_MODE=mysql` 时：

```powershell
npm run dev
```

业务状态保存在当前浏览器 localStorage；不同电脑 / 浏览器的数据不共享。

### 本机 MySQL

安装 MySQL 8.0，将连接写入不提交到 Git 的 `.env.local`，示例值应替换为本机实际配置：

```dotenv
DB_MODE=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=your_local_user
DB_PASSWORD=your_local_password
DB_NAME=canteen_guide_mvp
PORT=4174
```

运行 `npm run dev`。首次连接会按 `db.mjs` 创建数据库 / 表，连接账号需要对应权限。MySQL 连接失败时服务不启动，不会静默切换到浏览器数据。

### 腾讯云 MySQL

```powershell
npm run dev:remote
```

按提示输入远端密码，输入不回显；密码仅供当前进程使用，不写入仓库。脚本已含默认云数据库域名、端口、root 用户及 `canteen_guide_mvp` 名称。老师使用远端模式不需要安装本机 MySQL，但电脑必须能访问云端数据库，网络策略需允许连接。

服务默认打开 `http://127.0.0.1:4173/`。如果本机 `.env.local` 或 PORT 设置了 4174 等端口，以终端输出为准；新克隆的仓库没有 `.env.local`，通常使用 4173。服务只监听本机回环地址，不能从其他电脑直接访问。浏览器使用 127.0.0.1 地址以符合当前操作 API 的来源检查。

同一端口只能启动一个服务。更新后先在旧终端按 Ctrl+C，再重启；终端关闭后服务停止。需要换端口时，PowerShell 可先执行 `$env:PORT=4175`。

## 2. 主要功能

| 模块 | 当前能力 |
| --- | --- |
| 目录 | 两校区切换、食堂搜索、食堂 / 店铺 / 菜品详情、目标层级和刷新路由 |
| 资料共建 | 新食堂、新店、新菜品，单项 / 多项字段和经营状态申请；上级目标锁定 |
| 图片 | 食堂、门面、菜品多图；超过 900KB 压缩；缩略图 / 原图；分类、发布者、选填两百字描述 |
| 评论与帖子 | 三种目标评论、时间 / 赞同排序、富文本帖子、店铺模糊选择、帖子筛选和详情 |
| 态度与治理 | 标签 / 评论 / 帖子 / 共建的赞同反对、切换取消、禁止自评、阈值隐藏和人工复核 |
| 推荐票 | 每日一基础票、额外票保留、同店每日最多三票、自然周榜、唯一来源奖励 |
| 个人侧栏 | 四身份、审核消息与一键已读、我的发布概况、推荐票来源及消耗、累计积分占位 |
| 工作台 | 初审、暂示处理、固定争议、内容搜索筛选排序、管理员直接维护 |

图片描述与分类独立。放大底部例如“菜品照片 · 番茄面　发布人想说：这碗面刚出锅！”，未填时显示“未填写描述”。审核卡片与确认窗口显示完整位置、修改字段、价格、图片和描述，并可放大原图。

### 当前角色

| 身份 | 权限 |
| --- | --- |
| 发布人 / 浏览人 | 普通成员：浏览、投稿、投票、态度、共建、本人内容删除 |
| 审核员 | 普通功能，加初审 / 固定 / 驳回 / 撤销暂示、内容及固定争议复核 |
| 管理员 | 审核员功能，加校区、食堂、店铺、菜品、图片的直接维护和清空预览 |

审核员不显示直接维护、目录恢复或清空入口，直接维护方法在服务端仓库中也检查管理员身份。四种身份仍可自由切换，尚无学校会话，不能防止客户端伪造 actorId；**用于内部流程演示，不能按当前状态直接公开部署**。

### 当前规则

- 暂示 24 小时。五名不同用户赞同且赞同多于反对可自动固定；五名反对且不少于赞同则提前撤销。
- 评论、帖子、标签及固定共建集中反对的门槛为五人，且反对不少于赞同两倍；内容隐藏或固定资料转待复核。
- 评论五人赞同、帖子十人赞同或共建首次固定，各奖励一张；同一内容只发一次，反复取消再赞同不重复发奖。
- 北京时间每日基础票一张，先用基础票；额外票跨日跨周保留。同一店每天最多三张。
- 每周一零点开始新周榜，保留历史投票；并列按中文店名排序，当前没有历史榜单页面。
- 推荐票卡片可打开明细，新额外消耗记录准确 rewardKey，旧记录的来源对应关系标明推定。
- 积分暂按本人成功投票次数累计，不支持兑换；四身份中作者不能自评，自动五人 / 十人门槛无法仅靠这四个账号自然达到。

## 3. 数据存储

| 位置 | 保存内容 |
| --- | --- |
| `canteen_guide_mvp.app_state` | id=1 的一行 LONGTEXT JSON：目录、帖子评论、态度、申请、图片描述、已读标记、推荐票及奖励 |
| `app_media` | SHA-256 哈希、MIME、图片二进制 |
| `app_state_media_backup` | 首次分离旧内嵌图片前的状态备份 |
| `app_state_migration_backup` | 迁移覆盖已有目标数据时的状态备份，按需创建 |

角色在代码中，消息存于申请记录，积分从投票流水计算；没有独立用户、通知或积分表。本机和云端即使数据库同名，仍是两份独立数据，不自动同步。老师连同一云端数据库进行审核、编辑或投票，会改变共同数据。

图片卡片请求 160 / 320 / 640px WebP 缩略图，放大时加载原图；非首屏懒加载。图片哈希 URL 长期缓存，JS / CSS 使用 ETag，业务状态接口 no-store，页面刷新仍会读取全量状态。

`.env.local` 被 Git 忽略，静态服务不会提供该文件；真实数据库数据未导出到仓库。建表定义在 [db.mjs](./db.mjs)，文档保留 [schema 说明](./docs/03-技术与数据方案.md)。

## 4. 迁移与演示数据

```powershell
node scripts/migrate-mysql.mjs <目标主机> <目标端口> <目标用户名> canteen_guide_mvp
```

脚本从 `.env.local` 读取源库，交互输入目标密码，显示两端摘要；目标已有数据时保留状态备份，再要求输入 MIGRATE 执行复制。媒体引用与二进制一并迁移。首次运行旧数据会分离内嵌图片，可能耗时。

`node scripts/seed-demo.mjs` 要求已运行本机 MySQL 服务，当前脚本地址固定为 `http://127.0.0.1:4174`，并要求有适合食堂。它添加标记为“测试”的一店两菜、三条评论和一篇帖子，重复运行不重复添加同名资料。清空预览仅重置业务状态，不清除媒体表和备份表。

## 邮箱与密码登录（2026-10-13）

MySQL 模式使用 **邮箱 + 网站密码** 登录。注册、修改密码和找回密码需要邮箱验证码；首次注册均为普通用户。原有演示身份切换仅用于浏览器本地预览。

右上角入口打开中央登录窗口，提供登录、注册、忘记密码；登录后可从用户侧栏打开中央修改密码窗口。密码为 8–128 个字符，数据库仅保存随机盐与 scrypt 哈希。验证码有效期 10 分钟，会话有效期 7 天；修改或找回密码会撤销全部旧会话。

复制 `.env.example` 为 `.env.local` 并填入 QQ 邮箱 **SMTP 授权码**，不要填写邮箱登录密码。`.env.local` 已被 Git 忽略。运行 `node scripts/verify-smtp.mjs` 验证连接，修改配置后重启服务。

auth_users、auth_email_codes、auth_sessions、auth_rate_limits 在启动时自动建表或增量升级，旧数据保留。既有账户通过「找回 / 首次设置密码」设置网站密码，已有管理员或审核员角色保留。详见 [邮箱用户系统设计与 DFD](./docs/08-邮箱用户系统设计.md)。

测试：`node tests/email-auth.mjs`（独立临时本地 MySQL 数据库与模拟发信，不发送真实邮件）。

账户窗口交互回归测试：`node tests/account-dialog.mjs`（模拟账户与投递，覆盖输入框点击、密码草稿保留和重置后登录）。
