# 食间 · 校园食堂共建网站 MVP

更新日期：2026-10-18｜以当前源码及最近一次上线验收为准

**食间是一个由师生共同完善食堂和店铺信息、分享用餐体验，并通过评论与推荐票发现校园美食的网站。** 覆盖两个校区，不设置星级或分数打分。

体验地址：[食间 · 校园食堂共建指南](https://shijian-canteen.app.workbuddy.host/)。截至 2026-10-18，消息中心、帖子图片展示及历史管理员帖子归属修复已上线并完成验收。

> 当前版本使用 **Node.js + JSON 文件存储**，由 WorkBuddy 托管运行，已不再连接本机或腾讯云 MySQL。仓库中的早期 MySQL 说明属于历史设计；当前不存在 `npm run dev:remote` 命令。

## 1. 当前功能

| 模块 | 已实现能力 |
| --- | --- |
| 食堂目录 | 两校区切换、食堂搜索、食堂 / 店铺 / 菜品详情、层级导航与可直接访问和刷新的详情路由 |
| 店铺资料 | 图片、位置、营业时间、菜品名称或口味、参考价格、多个标签、营业与供应状态 |
| 资料共建 | 新食堂、新店、新菜品、图片和单项资料修改申请；从详情页申请时锁定所属目标 |
| 审核与暂示 | 管理员 / 审核员审核，可暂示、直接固定、驳回、撤销或复核；暂示区展示所属位置、具体修改值及图片 |

| 互动治理 | 标签、评论、帖子及共建的赞同 / 反对；切换和取消态度、禁止自评、达到门槛后隐藏 / 撤销 / 复核 |
| 推荐票与积分 | 每日基础票、可保留的额外票、单店每日上限、周榜、一次性奖励；每成功投一票累计一积分，兑换尚未开放 |
| 用户系统 | 邮箱与网站密码登录，注册 / 修改密码 / 找回密码使用邮箱验证码，普通用户 / 审核员 / 管理员权限分工 |
| 个人侧栏 | 推荐票余额、积分、我的发布、分类消息与已读管理 |
| 管理工作台 | 申请审核、评论 / 帖子 / 标签筛选与治理、按食堂筛选店铺、管理员直接维护、完整数据 ZIP 导出 |
| 手机适配 | 页头随内容增高，窄屏导航横向滑动；图片、登录窗口及用户侧栏支持移动端布局 |

### 消息中心

| 分类 | 内容 |
| --- | --- |
| 系统消息 | 额外推荐票奖励及来源、投票消耗及所用票来源、投票所得积分 |
| 我的消息 | 共建申请进度与最新审核结果 |
| 回复我的 | 其他用户对自己正常展示帖子的有效评论，支持打开原帖 |

三类均有未读计数，支持单条已读和覆盖全部分类的一键已读；按时间降序展示，可继续加载历史消息。进入消息中心会重新读取数据。自己的评论、已隐藏或删除内容不作为有效回复展示。

推荐票卡片保留余额概览，**来源与消耗记录已经移到系统消息**。历史投票若没有准确关联奖励来源，会标注为推定；每日基础票自动更新，不虚构历史领取消息。

### 图片展示约定

- 食堂、店铺和菜品图片可填写最多 200 字的个人描述；审核时可查看，放大后显示图片分类、上传者和描述。
- **美食贴正文图片不再填写图片描述，放大底部仅显示“美食贴图片”。** 旧帖中的描述属性也不会继续展示。
- 大图会在上传时尝试压缩到允许范围；卡片请求较小尺寸，放大时加载原图。

## 2. 本地运行

推荐使用项目已验证的 **Node.js 24** 与 npm。当前仓库没有 `package-lock.json`，首次安装使用 `npm install`，不要直接使用 `npm ci`。

```powershell
npm install
# 仅首次创建配置，-NoClobber 防止覆盖已有文件。
Copy-Item .env.example .env.local -NoClobber
```

编辑 `.env.local` 后启动：

```powershell
npm run dev
```

默认访问 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。端口以启动日志为准；已有 `.env.local` 或环境变量可能指定其他端口。停止服务在对应终端按 **Ctrl+C**；配置和服务端代码修改后需要重启。

服务监听 `0.0.0.0`，具备从其他设备访问的条件，实际访问还取决于网络和防火墙；反向代理或自定义域名应配置正确的来源白名单。同一端口只能运行一个服务，`EADDRINUSE` 表示端口已被占用。

### 配置说明

读取优先级：`.env.example` → `.env.local` → 进程环境变量，后者覆盖前者。

| 配置项 | 用途 |
| --- | --- |
| `PORT` | 服务端口，默认 4173 |
| `DB_MODE` | 默认 `file`，启用服务端 JSON 持久化；`none` 为浏览器演示。名称沿用早期设计，不代表当前仍接入 MySQL |
| `DATA_DIR` | 服务端数据目录，默认 `./data`；相对路径以启动工作目录解析 |
| `SMTP_HOST` / `SMTP_PORT` | 发信服务器，QQ 邮箱一般为 `smtp.qq.com` / `465` |
| `SMTP_USER` / `SMTP_PASS` | 发信邮箱及 **SMTP 授权码**，不是邮箱登录密码 |
| `AUTH_CODE_SECRET` | 随机生成并长期保存的验证码摘要密钥，重启时保持一致 |
| `AUTH_COOKIE_SECURE` | 本地 HTTP 为 `false`；公开 HTTPS 部署应配置为 `true` |
| `AUTH_ALLOWED_ORIGINS` | 反向代理下允许的完整网站来源，多个来源用逗号分隔 |
| `LEGACY_ADMIN_ACCOUNT_EMAIL` | 指定历史 `demo-admin` 帖子应归属的正式管理员邮箱；独立新站应留空 |

模板含当前站点的公开域名和历史管理员迁移邮箱。复制为独立项目时请按自己的站点调整，真实授权码与密钥只放在本地受保护配置或平台支持的秘密配置中。

未配置邮件仍可启动和浏览，但注册、找回及修改密码的邮件验证无法完成。填写有效 SMTP 配置后，可执行以下命令检查连接与授权，**不会发送邮件**：

```powershell
node scripts/verify-smtp.mjs
```

### 浏览器演示模式

需要无服务器持久化的界面演示时，在 `.env.local` 设置 `DB_MODE=none` 后重启。业务数据存于当前浏览器 localStorage，四个演示身份可切换；不同浏览器的数据不共享。此模式没有真实邮箱会话，不能代替线上账号权限验证。

**文件模式不会因为没有 `.env.local` 就自动退回浏览器存储**；默认仍启用 JSON 文件存储。

## 3. 登录与角色

- 登录使用邮箱和网站密码；注册、修改密码和找回密码需要邮箱验证码。
- 新注册账号均为普通用户，不能自行取得审核员或管理员权限；角色由服务端可信数据维护，目前没有自助提权入口。
- 登录 / 注册 / 找回密码在页面中央窗口中进行，个人信息与消息在侧栏中展示。
- 网站密码使用随机盐与 scrypt 哈希保存；验证码有效期 10 分钟，会话有效期 7 天。修改或找回密码会撤销旧会话。
- 服务端使用 HttpOnly、SameSite Cookie 保存会话，操作接口绑定真实登录身份，不信任客户端传来的角色或 actorId。

| 身份 | 权限 |
| --- | --- |
| 未登录访客 | 浏览公开目录、帖子和评论；参与发布、互动和投票需要登录 |
| 普通用户 | 发布帖子和评论、资料共建、投票与态度、删除本人发布的相关内容、查看本人消息 |
| 审核员 | 普通用户功能，加申请审核、暂示 / 固定 / 撤销、评论帖子等内容治理与争议复核；不能直接修改目录资料 |
| 管理员 | 审核员功能，加校区 / 食堂 / 店铺 / 菜品 / 图片直接维护，以及完整备份导出等管理能力 |

同一浏览器配置中的标签页共享登录 Cookie，后登录的账号会成为其他标签页刷新后的账号。双账号测试可使用不同浏览器、不同浏览器用户配置，或普通窗口与无痕窗口。

### 历史管理员帖子兼容

早期管理员帖子曾保存为 `ownerId=demo-admin`，与正式账号 ID 不同。服务器启动时依据 `LEGACY_ADMIN_ACCOUNT_EMAIL`，仅在邮箱唯一匹配到正常管理员时迁移这些帖子的归属，并保留 `legacyOwnerId`。

迁移不会按昵称匹配，不会认领 `demo-author` 或无归属帖子；重复启动不会重复写入。对应旧帖子奖励只调整归属，不重新发奖，历史自身互动也同步绑定。2026-10-18 已在线上完成两篇旧帖迁移，管理员可收到其已有及新增的有效评论消息；用户名为字符串 `null` 不影响此功能。

## 4. 互动与推荐票规则

- 共建申请经审核可暂示 **24 小时**，也可直接固定。
- 暂示内容获得至少 **5 人赞同**且赞同多于反对时自动固定；至少 **5 人反对**且反对不少于赞同时提前撤销。
- 评论、帖子和标签至少 **5 人反对**且反对不少于赞同的两倍时，可触发自动隐藏；已固定共建达到该条件后进入争议复核。人工治理锁定的内容按管理规则处理。
- 评论获 **5 人赞同**、帖子获 **10 人赞同**或共建首次固定，各奖励一张额外推荐票；同一来源只奖励一次，取消后重新赞同不会重复领奖。
- 按北京时间每日提供 **1 张基础票**，当日优先使用；额外票可跨日、跨周保留，同一店每天最多投 **3 张**。
- 每周一零点进入新周榜，历史投票记录保留，不物理删除；票数并列按中文店名排序。
- 每成功投一票累计 **1 积分**，目前仅展示，兑换功能未开放。
- 不支持多层回复；“回复我的”当前指其他用户对本人美食贴的评论。

详细规则见网站“网站评价规则”及 [互动与推荐票规则文档](./docs/07-互动与推荐票规则草案.md)。

## 5. 数据存储与备份

技术栈为原生 HTML / CSS / JavaScript、Node.js HTTP 服务、Node 内置文件系统与 Nodemailer；当前无需外部数据库服务。

| 位置 / 字段 | 保存内容 |
| --- | --- |
| `data/app-data.json` | 当前服务端存储文件；目录受 `DATA_DIR` 配置控制 |
| `state` | JSON 字符串：校区、食堂、店铺、菜品、共建、评论、帖子、态度、推荐票、奖励和消息已读回执等 |
| `users` | 邮箱账号、角色、密码哈希等 |
| `codes` / `sessions` / `rateLimits` | 验证码摘要与状态、会话摘要与有效期、频率限制 |
| `media` | 图片哈希与 MIME 索引 |
| `data/media/<hash>` | 图片二进制文件，独立于 JSON 保存 |

文件写入使用进程内串行事务与临时文件原子替换。此实现面向单服务实例，不是多进程 / 多副本共享数据库方案。复制仓库到另一台电脑运行，**不会自动连接线上数据或同步线上内容**。

消息由现有业务记录生成：审核已读沿用 `notificationReadAt`，系统与回复消息的已读保存于 `messageReadReceipts`。积分由成功投票流水计算，没有独立积分账户表。

### 图片与加载

服务端图片使用哈希 URL；图片接口支持请求 160 / 320 / 640px 尺寸。运行环境若有可用的 `sharp`，可返回缩略图；当前依赖清单未包含 `sharp`，不可用时会返回原图，不能保证每次都获得更小的 WebP 文件。前端另有上传压缩、图片懒加载和放大预览。

静态 JS / CSS 使用 ETag，图片使用缓存；业务状态接口为 `no-store`，页面刷新仍会读取状态，当前没有增量同步 API。

### 备份与历史种子

管理员可在工作台“导出全部数据”，下载包含 `app-data.json` 与媒体文件的 ZIP。备份包含账号和会话相关数据，应保存在仓库和公开下载目录之外。当前没有网页导入接口；恢复需停服后由维护者核对文件结构、数据目录和媒体，再恢复并验证。

仓库保留 `seed-data.json` / `seed-media/` 作为历史迁移资料。`db.mjs` 在空存储条件满足时可能用它们初始化业务数据、用户和媒体，**它们不是线上实时备份**；独立新站首次启动前应明确是否需要这些历史数据。当前更新发布包明确不包含种子，也不会用种子覆盖线上数据。

`.env.local`、环境配置副本、备份、`data/`、`.npm-cache/`、`.deploy/` 和 `node_modules/` 由 Git 忽略规则管理；Git 忽略并不代表第三方发布工具一定忽略，发布使用下一节的白名单打包。

## 6. 已验证的 WorkBuddy 更新流程

2026-10-18 已使用 **干净发布目录 + 原 appId + 标准应用清单** 两次更新原应用，保留原链接和原沙箱。此前“换目录必然新建应用”的结论不完整；仅重复使用相同 `domainPrefix` 也不能保证复用。

本地生成发布包：

```powershell
node scripts/prepare-deploy.mjs
```

脚本每次在 `.deploy/release-*` 创建新目录，复制运行文件、公开配置示例与原应用清单，生成含 SHA-256 的 `release-manifest.json`；不删除旧发布包，不移动工作区文件，**不复制密钥、缓存、种子、媒体或运行数据**。生成发布包不等于已经部署。

| 发布参数 | 当前配置 |
| --- | --- |
| 目标 | 更新原“食间”应用，appId `wbapp_mkles2WxzoQkUIOuWS1250` |
| directory | 本次新生成的 `.deploy/release-*`，不要写死旧目录 |
| language / port | `node` / `4173` |
| domainPrefix | `shijian-canteen` |
| installCmd | `npm install --omit=dev --ignore-scripts` |
| startCmd | `node scripts/deploy-start.mjs` |

当前脚本和应用清单绑定本项目，不能不加修改地用于新建另一个站点。更新原应用需存在正确的应用清单和部署历史；部署前后核对实际应用、沙箱、链接和资源哈希。

现有更新流程复用原沙箱，以覆盖解压方式写入新代码，原配置、JSON 和媒体留在沙箱内，不随本地发布包重新上传。`deploy-start.mjs` 在启动服务器前验证原鉴权 / 邮件配置、管理员、业务 JSON 和媒体；缺失则退出，不初始化空环境。**该命令用于现有站点更新，不用于首次本地启动。**

Codex 负责开发、诊断、测试及打包，WorkBuddy 负责部署与线上验收。原配置目前仍在运行沙箱中，尚未完成平台环境变量 / 密钥配置迁移；复用沙箱不等同于具备灾备，更新前应保存独立备份。

最近上线版本：`post-image-replies-20261018`。本地历史验收材料位于 `.workbuddy/`；详细过程见 [部署改造与托管说明](./docs/09-部署改造与托管说明.md)。
