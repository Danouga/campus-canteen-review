# 互动、共建、推荐票与积分规则

版本：v0.3｜更新日期：2026-10-13｜当前 MVP 生效规则

文件名保留“草案”以兼容旧链接，本文正文已更新为当前代码规则。演示身份可自由切换，因此只能验证流程，不能据此证明真实用户防刷能力。

## 1. 态度与去重

标签、评论、帖子，以及暂示中或已固定的共建记录支持赞同和反对。每个 actorId 对同一对象只有一个当前态度，允许改选或取消；作者不能给自己表态。计数按不同 actorId 去重，不把重复记录当成不同用户；态度撤销后不继续计入当前数量。

## 2. 生效阈值

| 对象 / 行为 | 当前门槛 | 结果 |
| --- | --- | --- |
| 评论 / 帖子 / 标签隐藏 | 反对至少五人，且反对不少于赞同两倍 | hidden，交人工复核 |
| 暂示自动固定 | 赞同至少五人，且赞同多于反对 | fixed，应用候选资料，首次固定发奖 |
| 暂示提前撤销 | 反对至少五人，且反对不少于赞同 | rejected，不覆盖正式资料 |
| 固定资料争议 | 反对至少五人，且反对不少于赞同两倍 | contested，保留正式资料等待复核 |
| 评论赞同奖励 | 公开评论获得五名不同用户赞同 | 作者一张额外票，最多一次 |
| 帖子赞同奖励 | 公开帖子获得十名不同用户赞同 | 作者一张额外票，最多一次 |
| 共建固定奖励 | 人工直接固定、暂示人工固定或社区自动固定 | 申请人一张额外票，最多一次 |

隐藏标签不在公开 tags 中；评论显示折叠提示；隐藏帖子不在公开列表和详情中出现。审核员与管理员可隐藏、恢复、移除评论、帖子和标签，人工恢复设置 moderationLocked，避免旧计数立即再次自动隐藏。

固定争议由审核员或管理员决定继续收录或撤销。撤销依据 applied 引用或快照恢复 / 下架相关资料；它不是完整的多版本审计。审核员不能直接新增或修改目录资料；管理员拥有直接维护权限。

## 3. 暂示、状态和消息

暂示期为审核后 24 小时；候选资料独立展示，不覆盖正式字段。页面加载及打开页面后的每分钟检查可处理到期，没有独立服务端任务。

店铺经营状态为正常营业、暂示闭店、下架；下架店铺仍显示，但不接收推荐票。菜品为可售、下架；下架菜品退出公开列表。状态申请记录原状态，固定前发现状态已经变化时拒绝旧申请覆盖。

审核结果、到期和争议状态通过本人共建申请显示在“我的消息”。支持单条与一键已读，只处理本人非 pending 且未读申请；审核状态再变化会重置未读标记。评论隐藏和奖励发放尚无独立消息类型。

## 4. 推荐票与周榜

- 北京时间每日一张基础票，当日未使用不结转。
- 额外奖励票跨日、跨周保留；先用基础票，再用未消耗的额外票。
- 同一用户对同一家店每天最多三张，基础与额外合计；余额不足或店铺经营下架时不能投票。
- 周榜按 week 统计，周一 00:00 开新周；不物理清除旧投票，不清除额外票。
- 当前并列票数按中文店名排序。首页显示本周前三，推荐榜显示全部可展示店铺；尚无历史周榜页面或低参与店铺探索算法。
- 成功投票不可自行撤销；当前也没有管理员冲正接口。

## 5. 一次奖励与来源追溯

奖励 key 为“来源类型 + 内容 ID”，同一来源只能发一张。取消再赞同、恢复达标、重复查看或审核不会为同一来源新建第二条奖励。本人态度和同一人的重复记录不计入人数。隐藏或移除内容不新获得赞同奖励，已发奖励不会因普通取消赞同自动收回。

个人概览的推荐票卡片可打开明细：奖励类型、原内容、获得时间、是否已使用，以及投票目标、时间和票源。新额外票保存 rewardKey，能关联具体奖励；旧投票缺少该字段时按未分配奖励顺序推定并明确提示。旧记录推定关系不等于当时已保存的精确来源。

MySQL 操作事务通过 app_state 行锁串行检查余额和日上限。当前没有请求幂等键、每周奖励上限、待发奖励、刷赞检测、封禁或冲正流程。

## 6. 积分

暂按本人每次成功投票累计一分，积分直接由投票流水数量计算，避免额外维护另一份余额。无独立积分表、扣分、到期或兑换。学校周边、学习用品兑换属于后续合作设想。

## 7. 演示限制与后续规则

四种身份为发布人、浏览人、审核员、管理员。每条内容的作者不能自评，因此只能从另外三个演示身份取得态度，不能自然达到五人或十人门槛。自动门槛通过测试记录验证。

正式用户开放前需要学校身份、服务器可信会话、频率和异常互动检查、举报申诉及操作审计。奖励上限、冲正、封禁票处理和规则版本必须另行确认，不能把早期建议值当成当前规则。角色校验已经存在，但尚不能防止客户端冒用其他演示 actorId。
