# 产品需求规格说明书（PRD）

版本：v0.1｜日期：2026-10-02

## 1. 产品定义与边界

面向学校两个校区食堂的店铺信息与社区评价网站。核心评价方式是**推荐票、文字评论和美食贴**；没有星级、分数或综合评分。推荐票排行榜只表示该周期的用户推荐热度，不代表食品安全、价格或客观质量。首版目录允许完全空白，从共建逐步填充，移动端优先，桌面端可用。

### 1.1 角色与权限

| 角色 | 可执行操作 |
| --- | --- |
| 游客 | 浏览食堂、店铺、菜品、榜单和公开帖子；搜索与筛选 |
| 注册用户 | 游客权限；投票、评论、发帖、互动、收藏、申请共建、举报、申诉、管理自己的内容 |
| 审核员 | 查看待审队列、处理举报/申诉、隐藏或恢复内容、处理共建争议；无系统配置权限 |
| 管理员 | 审核员权限；可直接添加、编辑、删除食堂/店铺/菜品等资料，维护用户权限与规则，查看操作日志 |

经营者认领若后续实现，应作为受限角色，只能提交资料修改申请与回应，不能删除或改写用户评论。

### 2.1 店铺详情的数据来源标识

空白字段展示“暂无信息”和加号按钮；新店从食堂页的加号申请，不要求先有店铺记录。正式资料与暂示信息在视觉上区分。暂示内容标注“用户申请，待确认”，显示剩余时间、赞同/反对数和举报入口；固定内容标注最近确认时间。关店等重大变化在核实前不应让暂示内容覆盖原店铺营业状态。

### 3.3 推荐票与排行榜

**确定需求：** 每位用户每日有 1 张基础推荐票；每周店铺推荐票从零开始；存在基于内容赞同和共建固定的额外推荐票；按票数排行。

**建议规则（参数可配置，尚待确认）：**

1. 时间统一使用 `Asia/Shanghai`。每日周期为 00:00–次日 00:00；每周周期为周一 00:00–下周一 00:00，采用左闭右开区间。
2. 每日基础票 1 张，不可累积，未用当日失效。额外获得的推荐票进入用户票钱包，**可跨日、跨周保留**，不随店铺周榜清零；奖励票发放后的保留期限暂不设自动到期。每人每周最多即时发放 3 张奖励票，超出部分记为“待发奖励”，在后续周依次发放。
3. 单用户对同一店铺**每天最多投 3 张**（基础票与奖励票合计）。后台不能静默修改已开始的周期规则。
4. 成功投票后不允许自行撤销；管理员只可按明确原因做冲正流水。投票、票额扣减和店铺本周票数更新必须作为一个事务。
5. 榜单按本周有效推荐票降序；同票按最早达到当前票数的时间升序，再按店铺 ID 升序。展示周周期与更新时间；历史榜单保留快照。
6. “周清空”指开启新周榜并将新周期计数从零开始；历史流水和上周榜单不删除。周切换任务可重试，不得重复归档。
7. 被封禁账号的票是否保留，由管理员按滥用证据处置并记录；不批量隐形改榜。

| --- | --- | --- |
| VOTE-01 | P0 | 登录用户能查看今日基础票、奖励票余额和下一次重置时间 |
| VOTE-02 | P0 | 票额不足、重复点击、同店当天超过 3 张、跨日/跨周、并发请求均不得造成多投或负余额 |
| VOTE-03 | P0 | 店铺页和榜单的票数一致；榜单标明周期与同票规则 |
| VOTE-04 | P1 | 赞同与共建奖励发放、待发、使用及冲正均可在用户流水中查询；奖励票不自动到期 |

### 3.4 店铺评论与互动

| 编号 | 优先级 | 要求 |
| --- | --- | --- |
| COM-01 | P0 | 登录用户在店铺下发表文字评论，支持编辑/删除自己的评论；保留审核版本 |
| COM-02 | P0 | 对别人评论可选“赞同”或“反对”，每用户每条评论只有一个当前态，可切换或取消；不能评价自己 |
| COM-03 | P0 | 展示赞同与反对计数，计数应与有效互动记录一致 |
| COM-04 | P0 | 到隐藏阈值时评论从公众列表隐藏，作者可见状态和申诉入口，审核员可复核恢复 |

**建议隐藏阈值：**有效反对人数 ≥ 5 且反对数 − 赞同数 ≥ 3，触发“隐藏待审”。这是内容治理信号，不认定内容真假。隐藏后通知作者；审核员可以恢复、删除或维持隐藏，操作留痕。举报入口始终可用，严重违规不等待票数阈值。

| --- | --- | --- |

| POST-02 | P1 | 帖子详情显示作者、发布时间、编辑时间、关联店铺、正文、图片及评论 |

| POST-04 | P1 | 作者可编辑/删除帖子；已被隐藏或删除的帖子不进入首页推荐和店铺相关帖子 |

帖子应避免构成未经标识的广告。后续赞助内容须与自然帖子区分并标注。

### 3.6 赞同奖励票

**建议规则：**一条用户原创评论或帖子首次达到 **10 个不同有效用户赞同**，且赞同数 − 反对数 ≥ 8，作者获得 1 张奖励票。每条内容终身至多奖励一次；作者自赞、被封禁账号、判定异常的互动不计。每用户每周最多即时发放 3 张奖励票，超过上限的已达成奖励排队到后续周发放。奖励只在内容公开且未被判定违规时发放；后续发现刷赞，可冲正未使用奖励或冻结相当票额，已使用的票由管理员决定是否冲正并留痕。具体阈值待运营确认。

| 编号 | 优先级 | 要求 |
| --- | --- | --- |
| REWARD-01 | P1 | 奖励判定在互动事务后执行，幂等；同一内容不能重复发奖 |
| REWARD-02 | P1 | 用户能看到奖励来源、待发/发放时间、使用/冲正状态；奖励票不自动到期 |
| REWARD-03 | P1 | 被删除/隐藏的内容暂停奖励资格，申诉恢复后可重新评估 |

### 3.7 用户共建

申请类型：新店、关店、店铺迁址/位置纠错、菜品新增/修改/下架、店铺图片新增/替换、分类修正。所有申请需关联目标对象；新店申请要选食堂与位置。图片上传先进入隔离区，检查格式、尺寸、内容及版权确认后才公开暂示。

**建议状态流：**

`草稿 → 待管理员审核 → 暂时展示（24小时）/直接固定/驳回`；暂示后可 `已固定 / 已撤销 / 已过期`；固定后如果达到反对阈值，则 `已固定 → 复核暂示（最多24小时） → 恢复固定 / 已撤销`。管理员先核验申请，决定暂示或直接固定；高影响变更（关店、迁址、新店）应有更严格核验。管理员也可直接编辑或删除正式资料，所有操作可追溯。

**建议阈值：**暂示期累计不同有效用户赞同 ≥ 8 且净赞同 ≥ 5，达到固定条件；反对 ≥ 5 且净反对 ≥ 3，提前撤销；24 小时未达任一条件则过期。已固定申请再收到不同有效用户反对 ≥ 5 且净反对 ≥ 3 时，降为“复核暂示”，其变更从正式字段暂时回退到上一已确认版本。管理员复核后恢复或撤销。每申请人不能对自己的申请投态度票。

**重要解释：**固定的是一条可追溯的资料版本，不是永久不可改。共建记录永不靠定时任务物理删除；过期与撤销仅改变公开展示状态，按数据保留政策处理底层记录。

### 3.8 基础推荐与发现

首版不做 AI。首页分两个清楚命名的栏位；没有有效数据时展示共建入口而非空白榜单：

- **本周热门**：依据当前周有效推荐票排序，去掉关店/被隐藏店铺。可加时间衰减形成“最近热度”，但须明确算法公式与展示标签；最简单首版直接用本周票数。
- **去发现**：在资料完整、营业中且近期评价参与量偏少的店铺中轮换；为防冷门栏被低质或关闭店铺占据，可设最小资料完整度和管理员排除项。

每次推荐需说明依据（例如“本周 23 张推荐票”或“近 14 天评价较少”），提供查看全部店铺入口。随机轮换可按日固定种子，避免每次刷新乱跳。个人画像、位置追踪和 AI 推断不进入首版。

## 4. 核心用户流程

1. **找店**：游客进入首页 → 选择食堂/搜索店名 → 筛选分类 → 进入详情 → 看位置、菜品、图片、评论和帖子。
2. **投票**：用户登录 → 看到今日可用票 → 店铺页点击推荐 → 服务端校验身份、当日同店限制和余额 → 成功后票数与榜单更新 → 显示流水。
3. **评论/互动**：用户发布评论 → 其他用户赞同/反对 → 达奖励或隐藏阈值时异步判定 → 作者收到通知，必要时可申诉。
4. **发美食贴**：选择店铺 → 编辑标题/正文/图片 → 提交发布 → 帖子进入店铺关联列表 → 他人评论、收藏与投态度票。
5. **共建**：从空白食堂页或店铺缺失字段点击加号 → 选择变更类型并提交证据 → 管理员审核 → 暂示或直接固定/驳回 → 暂示时其他用户表态 → 固定/撤销/过期 → 固定后发奖励；若遭质疑则复核并可回退。

### 5.1 关键验收用例

- 同一账号对同一店铺同一天最多成功投 3 张；并发点击不能超过票额或上限，无负余额。
- 周日 23:59:59 与周一 00:00:00 的票分别计入不同周，历史榜单可查。
- 内容赞同达到奖励阈值的并发请求只发 1 张奖励票；作者本人表态不计数。
- 评论达到隐藏阈值后游客不可见，作者可查看原因与申诉，审核员可恢复。
- 未经管理员初审的共建申请不公开；审核员可选择暂示或直接固定；暂示超时后自动过期；固定资料受到有效反对后能回退到上一版本，图片和菜品关联不丢失。
- 两校区空白食堂页有可用加号入口；价格和营业时间未知时显示待补充；管理员直接编辑/下架后审计记录可查。
- 用户删除/注销请求、举报、申诉均可从页面找到入口并进入处理队列。

## 6. 明确排除与待决事项

**排除：**星级打分、商品交易、线上点餐、配送、食堂官方认证、实时排队/库存。三维告示牌、AI 推荐、小程序、赞助均不进入首版验收。

**后续入口：**三维食堂、AI 推荐、微信小程序、赞助可在导航或个人中心预留“规划中”说明页；当前阶段不提供会让用户误以为已上线的操作入口。

**待决：**学校接口申请结果、各食堂名称与营业时间、屏蔽词库来源及误判处理、游客帖子可见性、各互动阈值、图片授权、审核负责人及服务时限。两校区、基础票每天 1 张、奖励票保留、同店每天最多 3 张和暂不开放评论回复已确定。详见[实施计划](./04-实施计划与待确认事项.md)。
