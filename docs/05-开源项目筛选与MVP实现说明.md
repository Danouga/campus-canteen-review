# 开源项目筛选与 MVP 实现说明

日期：2026-10-03

## 筛选标准

优先考虑可改造的校园食堂或餐饮发现网站，并检查公开许可证、功能重合度、依赖复杂度、数据层能否暂时脱离租用数据库。关键匹配点是：两校区空白目录、用户申请补充资料、管理员先审后暂示/固定、没有星级打分或交易流程。

| 项目 | 可借鉴部分 | 与本项目的主要差距 | 结论 |
| --- | --- | --- | --- |
| [FoodVice](https://github.com/codesbymusab/FoodVice) | React 前端、餐饮发现、社区与审核模块；README 声称 MIT | 依赖 MongoDB、Firebase、Google 地图/登录和 AI 服务；以餐馆地图、评分、短视频为中心，重做空白共建与票制成本高 | 不直接改造 |
| [CampusEats](https://github.com/Ravindu-Dev/CampusEats) | 校园食堂与店铺概念 | 主线是预订、支付、取餐；仓库说明为私人团队项目，未看到可供改造的明确开放许可 | 不直接改造 |
| [Restaurant Management System](https://github.com/ductaip/Restaurant-Management-System) | MIT、菜单与管理后台界面 | 主线是扫码点餐、桌位、订单和实时厨房流程；要删除大量不相关模块，再建共建审核 | 不直接改造 |
| [test-restaurant-app](https://github.com/tislib/test-restaurant-app) | 餐馆创建、投票、文字评论 | Angular/Spring/Metronic/Kubernetes 技术栈较重，且公开结果未能确认完整许可证与当前适配性 | 不直接改造 |

结论：未找到适合在本轮直接修改的完整项目。为保持 MVP 简单、让数据层可替换，当前实现使用原生 HTML/CSS/JavaScript 和 Node.js 内置静态服务器，不复制上述仓库代码或素材。后续若选用开源组件，应记录版本与许可证。

## 已实现

- 两校区切换、空白食堂页、搜索与食堂/店铺详情。
- 清新、低饱和度的响应式视觉；桌面与手机浏览器均可浏览。
- 共建申请：食堂、店铺、菜品、食堂时间、图片、店铺信息。
- 管理员预览：审核为暂示 24 小时/固定/驳回，直接编辑或下架、恢复食堂和店铺，管理菜品与图片，修改校区名称。
- 本地评论演示和简单屏蔽词筛选；未来功能说明页。
- 统一的异步数据访问接口，当前使用本地适配器，服务端适配器保留方法签名。

## 下一阶段接数据库前需确认

1. 数据库类型与版本、部署环境，以及是否已有表结构；不要把数据库密码放进前端。
2. 后端服务的部署位置、域名与 HTTPS 方案；浏览器应只访问后端 API。
3. 学校登录接口申请结果、可获得的用户标识、管理员权限来源。
4. 图片对象存储方案、真实屏蔽词库来源和内容审核安排。
5. 票制、帖子和共建态度功能何时进入服务端实现。

当前本地适配器仅供界面试用。正式上线需要服务端身份验证、权限检查、审核日志、图片处理与持久化。
