# 实施计划、测试与待确认事项

版本：v0.3｜更新日期：2026-10-13

当前已完成可在内部演示的目录、社区、票制、审核和 MySQL 数据流程。后续计划围绕正式身份、安全、数据规模和学校试点展开，不再把已有推荐票或数据库连接列成未开始任务。时间安排需要按实际单人开发投入和学校接口结果重新估算，本文不把早期粗估工期当作当前承诺。

## 3. 当前测试脚本

执行前先安装依赖。规则测试使用独立内存状态，不写云端业务数据。

```powershell
npm run check
node tests/contribution-smoke.mjs
node tests/status-updates.mjs
node tests/reactions-moderation.mjs
node tests/recommendation-votes.mjs
node tests/reviewer-permissions.mjs
node tests/image-descriptions.mjs
```

| 脚本 | 主要覆盖 |
| --- | --- |
| contribution-smoke | 共建目标、字段、审核消息、单条和一键已读、本人内容删除、菜品多图 |
| status-updates | 店铺 / 菜品状态申请、暂示和固定、旧状态防覆盖 |
| reactions-moderation | 标签态度、隐藏复核、四票 / 五票暂示边界、固定争议 |
| recommendation-votes | 基础 / 额外票、每店上限、上海日周边界、来源绑定、去重、自赞排除、反复赞同、并发点击 |
| reviewer-permissions | 审核员允许审核、拒绝直接维护；成员 / 缺失身份拒绝；API 适配器传递身份 |
| image-descriptions | 描述选填、长度、发布者、直接 / 暂示固定、编辑保留与清空描述 |

`node tests/media-storage.mjs` 另依赖可用的本机 MySQL 和 `.env.local`：它创建临时测试数据库，验证媒体迁移、备份、独立读取和缩略图，结束后清理测试库。运行前应检查所用连接；不要把它误当成云端生产压力测试。

### 3.1 页面人工验收

- 切换审核员：存在审核工作台，直接维护、目录恢复、清空入口不出现。
- 用成员提交图片及描述：工作台和确认弹窗显示完整路径、字段和图片描述，图片能放大；固定后描述仍存在。
- 在菜品详情修改字段，店铺列表区域只导航，不触发菜品修改表单。
- 评论、帖子和标签态度变化后数量和公开状态一致；排序、状态筛选、搜索及展开更多可用。
- 投票后概览票额、周榜、来源与消耗明细、累计积分一致。
- 一键已读只清除本人的已处理消息；审核状态再次改变时重新出现未读。
- 详情页刷新及返回上级正常；手机宽度下导航、表单、图片描述不溢出。

这些页面检查需要在浏览器中实际执行，规则测试通过不能代替视觉验收。

## 4. 数据准备与演示

可以只建立两个校区和少量已知食堂，不要求单人录入全部店铺。未知位置、价格、时间用“待补充”。演示数据要明显标记，不能当成真实学生评价或真实校方资料。

`node scripts/seed-demo.mjs` 当前连接 `http://127.0.0.1:4174`，要求已运行本机 MySQL 模式服务并有合适食堂；若端口不同，需要先调整脚本。它添加标记为“测试”的一店两菜、三条评论和一篇帖子，重复运行不重复添加同名内容。

同一云数据库连接下，老师审核或编辑会影响共同业务数据。本机和云端数据库并不同步；需要独立演示数据时，另建数据库并配置普通启动环境，不能把相同数据库名称当成数据隔离。

## 5. 当前限制与下一步验收

| 问题 | 当前限制 | 下一步目标 |
| --- | --- | --- |
| 身份冒用 | 演示角色和 actorId 可自由选择 | 服务端会话及可信角色 |
| 数据规模 | 全量 JSON、单行锁、全量状态读取 | 业务分表、分页、增量、并发测试 |
| 操作追溯 | 有票据、部分状态时间和应用快照，无完整操作人事件链 | 不可变审计与规则版本 |
| 自动任务 | 到期依赖页面触发 | 后台到期任务，重试与告警 |
| 反刷 | 同人去重、自评限制、奖励一次、日上限 | 真实身份、频率 / 异常互动识别、冲正规则 |
| 内容处理 | 少量演示词和前端富文本清理 | 服务端安全清理、真实词库、图片核验 |
| 媒体与备份 | 迁移备份不涵盖完整定期保护；无孤立媒体清理 | 数据 / 图片备份及恢复演练 |
| 积分 | 投票条数为累计积分，无兑换 | 学校确认兑换资源和积分流水 |

## 7. 待确认事项

| 项目 | 已确认部分 | 仍需确认 |
| --- | --- | --- |
| 校区与食堂 | 两校区结构，空白起步 | 真实名称、位置和首批食堂 |
| 学校登录 | MVP 延后对接 | 学校接口、可用用户标识和角色授权方式 |

| 推荐票 | 每日一张、额外保留、同店每日三张 | 奖励上限、异常撤销及历史周榜展示 |
| 图片描述 | 选填、最多两百字、发布者关联 | 版权确认、真实审核与投诉渠道 |
| 积分 | 每投一票累计一分的占位 | 可兑换资源、结算规则、有效期和审批 |
| 内容扩展 | 暂无回复、收藏、发布后编辑 | 优先级和可接受工作量 |

三维食堂、AI、小程序和赞助需分别确认授权、数据、运营及技术成本，当前只是未来计划页面。
